# 日常有因下一阶段命题调研

请在当前 VideoBrief 仓库启动一次“日常有因下一阶段命题调研”。本任务只为 B站账号“日常有因”选择下一条值得进入制作的视频命题，完成后停在 Topic Gate。

这不是首次账号方向探索，也不是视频生产、上传或发布任务。不要重新讨论账号名称或主平台；本轮只为当前双格式实验选择下一条命题，并判断它是否真的符合新的观众承诺。

## 当前决策基线

- 当前实验的观众承诺：从一个日常反常现象，追到最后谁得利、谁付钱、哪条规则在起作用。
- 更宽的编辑边界仍是全球产品、商业和互联网现象，但不能再仅凭“属于这个范围”批准命题。
- 前 30 天主平台：B站；正式生产默认单横版 `16:9 / 1920x1080 / 30fps`。
- 当前表现与结构基线：`docs/self-owned-video-format-direction-review-20260825.zh-CN.md`；2026-08-22 复盘只作历史对照。
- 当前风格实验：`content/workflows/self-owned-explainer-v1/style-experiment.json`，状态为 `active`；四个槽位固定为 2 条动作谜题型和 2 条利益冲突型。
- 已发布命题与排重基线：
  - 快递柜末端配送：`BV1uYuG6rEVz`；
  - 欧盟连体瓶盖：`BV1TYuG6rEQ8`；
  - 汽车实体按键与触屏：`BV1bYuG6rEii`。
- 近期表现复盘还覆盖：充电宝登机、电子价签、网约车一口价和行李追踪；具体发布目标、时间和指标从当前表现基线与 canonical projects 读取，不在提示词中复制易过期数字。
- 历史发布内容和近期四条复盘样本只证明已经生产并发布，不能证明市场需求、账号方向或永久垂类已经验证。
- 汽车实体按键样片已有明确负向审片反馈：“不好看、看不懂、没啥吸引人”。把它作为命题表达和开头吸引力的回归警示，不作为正向选题基准。

## 开始前与边界

1. 运行 `git status --short`，保留所有现有改动。
2. 只读检查 `AGENTS.md`、`README.md`、`package.json`、`docs/self-owned-explainer-production-playbook.zh-CN.md`、`docs/self-owned-video-format-direction-review-20260825.zh-CN.md`、`docs/self-owned-video-performance-review-20260822.zh-CN.md`、`content/workflows/self-owned-explainer-v1/style-experiment.json`、`docs/video-production-workflow-and-roadmap.zh-CN.md`，以及已发布内容对应的最新 canonical projects。
3. 实际打开可访问的 B站公开页和创作数据，记录查询时间。无法看到曝光、完播、关注来源等后台数据时，明确写为证据缺口，不得用公开视频页数据替代。
4. 全程区分仓库事实、平台公开事实、来源声明、用户反馈、分析推断和待验证假设。
5. 只做调研和决策建议：不修改仓库，不创建 canonical project，不下载或批量入库素材，不写脚本，不渲染，不打包，不上传，不发布。
6. 不用既有生产能力、内部 Topic Gate 评分、三条发布事实或单条偶然数据反推市场需求成立。

## 执行效率与交接

- 本任务只保留支持 Topic Gate 的证据。网页快照、命令日志和 canonical JSON 只读取所需字段，不把整页无关导航、整份发布台账或长日志反复带入上下文。
- 近 6-12 个月是主调研窗口；只有需要补充最近 30 天即时信号时才启动对应窄窗口调研，不为完成形式重复扫描同一平台。
- 搜索阶段先宽筛，得到 3 个入围题后再逐题打开来源、相似内容和素材。不要为 8-12 个候选都做同等级深读。
- Topic Gate 批准后另开干净生产任务，只交接唯一命题、已核验链接、证据边界、素材线索、目标信号和批准指纹；不要继承候选池、网页输出和下载日志。
- Canonical project 创建后，后续任务优先运行 `npm run project:context -- --brief=content/projects/<project-id>/project.json --stage=research|material|delivery`，只在投影缺字段或排查 schema 时读取完整项目。
- 长任务运行到成功、失败或明确超时后一次性返回结构化摘要，不高频轮询。冗余素材失败一次且核心覆盖已经满足时直接淘汰，不阻塞 Gate。

## 第一阶段：复盘真实发布反馈

先在 2026-08-22 基线之后追加已发布内容的同口径快照，尽可能记录：发布时间、视频时长、标题与平台实际封面、播放、点赞、投币、收藏、评论、分享、关注转化、2 秒跳出、平均观看、完播和可见评论问题。数据不可见就写“不可见”，不要估算，不得覆盖历史快照。

回答：

- 哪种标题和开头更容易让陌生用户理解“这和我有什么关系”；
- 哪条内容出现了收藏、评论、关注或重复问题等较强信号；
- 高表现与普通表现的差异更可能来自命题、包装、叙事、素材还是分发；
- 样本量太小、发布时间不同或曝光不足导致哪些结论仍不能成立。

不能只看播放量，也不能把三条之间的相对高低直接解释成永久方向选择。

## 第二阶段：调查当前受众问题

以 B站为主，核验近 6-12 个月与候选问题相关的中文搜索结果、近期内容和评论区；只有在能补充真实需求或同质化判断时，才查看小红书、抖音、视频号或知乎，不做泛平台矩阵报告。

重点寻找：

- 普通用户反复追问但没有被讲清的问题；
- 与日常体验直接相关的规则变化、成本转移、产品取舍和平台机制；
- 同类高表现内容与账号普通内容的差异；
- 现有内容只报道“发生了什么”，却没有解释“为什么、怎样运转、谁承担成本”的缺口；
- 第一层答案之后还能自然产生第二层问题的题目，而不是只能扩写定义和背景；
- 普通观众会先给出什么直觉答案，以及一手证据如何推翻或修正它；
- 搜索结果已经高度同质化、只能靠热点或情绪成立的方向。

平台案例只能证明内容形式和既有需求信号存在，不能证明新账号会获得同等流量。访问失败、数据不可见或样本不足必须单列为证据缺口。

## 第三阶段：建立开放候选池

提出 8-12 个彼此差异明显的新命题，至少覆盖 4 类不同的日常产品、服务或互联网场景，避免围绕已有三题做近似续集。候选必须先归入动作谜题型或利益冲突型；不能稳定归类的题目不进入本轮。每题必须回答：

- 观众正在经历的具体问题是什么；
- 为什么会点开、看完、收藏、评论或关注；
- 一句话命题和唯一知识收益；
- 核心矛盾、机制或反常识；
- 普通观众最可能给出的直觉答案，以及准备用什么证据推翻或修正；
- 第一层解释之后会升级成什么第二层问题；
- 动作谜题的类比回报，或利益冲突涉及的具体人物、金钱、规则和代价；
- 可以支撑核心事实的一手资料；
- 可访问的真实动态素材及其画面角色；
- 中文内容的同质化程度；
- 事实、权利、AIGC、审核和制作风险；
- 为什么它相对已发布内容有新增验证价值。
- 它适合验证动作谜题型的短时留存，还是利益冲突型的深看、讨论和关注；不得为了补实验槽位硬改命题。

不要推荐：泛资讯搬运、泛 AI 新闻、工具合集、旧项目复盘、VideoBrief 或制作教程、纯概念口播、依赖本人出镜或生活挑战、医疗法律金融建议，以及只能依赖侵权搬运、夸张标题或虚假画面成立的题目。

## 第四阶段：评分与三题核验

所有候选按 40 分统一评分：

- 受众问题强度：8 分；
- 首屏异常对象、动作、价格或结果：6 分；
- 直觉猜想、推翻与第二层问题：6 分；
- 所选格式的类比回报或利益代价：6 分；
- 一手证据质量：5 分；
- 动态素材表现力：4 分；
- 权利可行性：3 分；
- 对栏目承诺的新增验证价值：2 分。

评分必须给出证据理由，不能把主观“有趣”当成需求证据。核心事实缺少一手来源、主要画面只能依赖不可控侵权素材，或命题无法用一句普通中文讲清时，无论总分多高都淘汰。

从候选中选出方向差异明显的 3 题，逐题实际核验：

- 一手来源链接、发布日期、来源主体、能证明与不能证明的内容；
- 公开动态素材链接、发布者、清晰度、可用叙事段落、画面角色和权利状态；
- 真实素材不足时的原创信息层或明确示意方案；
- B站近期相似内容、可见表现、评论问题和同质化缺口；
- 一个不超过 15 秒的开头承诺，以及完整的问题升级路径；
- 动作谜题型首 3 秒的真实对象和明确动作、直觉猜想、推翻证据与类比回报；
- 利益冲突型开场的具体订单、价格或人物处境，以及至少两次问题升级、利益相关者和现实代价；
- 预计成片时长和最低可行制作复杂度。

公开可访问不等于允许复用，`official` 不等于 `cleared`。一手资料负责事实，第三方视频不能替代事实来源；相关素材和 AI 示意不能冒充特定事件或结果的真实记录。

## 第五阶段：唯一推荐并停在 Topic Gate

最终按以下结构提交：

1. 三条已发布内容的同口径反馈快照与证据限制；
2. 当前受众问题和同质化发现；
3. 8-12 个候选及 40 分评分表；
4. 3 个入围题的一手证据、动态素材、权利和叙事可行性；
5. 唯一推荐的下一题，以及不优先另外两题的具体原因；
6. 推荐题的一句话受众命题、所属格式、唯一知识收益、B站标题方向、开头承诺、直觉猜想、推翻证据、第二层问题、完整叙事骨架、建议时长、封面对象和默认横版规格；
7. 该题分别要验证曝光点击、2 秒或 3 秒跳出、平均观看秒数、平均播放比例、完播、收藏、分享、评论和关注中的哪些信号，并明确它占用 `suspense-stakes-dual-format-v2` 的哪个实验槽位；
8. 事实、版权、平台审核、AIGC 和生产风险；
9. 当前证据缺口和仍需用户亲自决定的问题。

结论只能有一个主推荐。不要用“都可以试试”回避取舍，也不要因为已有三类题材就推定永久垂类。

完成后停在 Topic Gate，等待用户批准一句话命题。不要创建 canonical project，不要开始写旁白或分镜，不要下载素材，不要渲染，不要上传，不要发布。用户批准后，应另开干净生产任务，用精简交接继续 canonical production、Material Gate、自动验收、Delivery Gate 和 Publication Gate。
