# 自营解释型内容生产手册

## 1. 文档地位

本文记录自营账号“日常有因”的下一阶段命题调研与 Topic Gate 之后的正式生产流程。仓库内的可复用启动提示词只负责为下一条内容做发布复盘、开放候选、三题核验和唯一推荐；命题批准后的生产必须另开任务。

它是自营账号的编辑与执行模板，不改变 VideoBrief 作为通用视频生产工作台的产品边界。渲染、素材和验收细节仍分别以 `docs/video-render-pipeline.zh-CN.md`、`docs/online-dynamic-material-cut-workflow.zh-CN.md` 和 canonical project 为准。

## 2. 为什么沉淀为仓库规范

本流程不单独创建全局 Skill，原因是它直接依赖本仓库的：

- `content/projects/<project-id>/project.json`；
- Topic、Research、Material、Delivery 和 Publication Gate；
- `materialQualityReview` 指纹；
- FFmpeg render manifest、technical proof 和完整解码；
- `/short-video` 的桌面与移动播放器验收。

这些契约离开 VideoBrief 不成立。把它们复制进全局 Skill 会产生第二份事实源，并可能在其他视频项目中误触发。仓库规范负责执行，页面负责聚合结果；只有未来出现多个仓库共同复用同一流程时，才应提炼为全局 Skill 并同步到 CcSwitch。

## 4. 完整流程

### 4.1 发布复盘与范围确认

先读取已发布内容的同口径数据、评论和可见反馈，再确认本轮排重、禁止题材、禁止动作和 Topic Gate。当前四条实验的观众承诺是：

> 从一个日常反常现象，追到最后谁得利、谁付钱、哪条规则在起作用。

这是待验证的栏目承诺，位于“讲清全球产品、商业和互联网现象为什么发生、怎样运转、会影响谁”的更宽编辑边界内，不改变 VideoBrief 的通用产品边界。选题必须由真实观众问题、连续悬念、证据条件和素材可行性共同决定；发布、内部评分和相对播放高低都不等于市场验证。

#### 当前数据基线与风格实验

2026-08-25 对当前方向 12 条解释视频完成结构与市场复盘：总播放 2952，显性互动率约 0.78%，11 条成熟视频平均 3 秒跳出约 42.16%、平均播放比例约 41.11%，关注转化接近零。连体瓶盖的真实反常动作和网约车的成本分配冲突是相对正向信号，但旧脚本都过早交付答案，并让内部证据边界连续进入旁白。

完整账号基线、B站高表现样本、结构诊断和证据限制见 `docs/self-owned-video-format-direction-review-20260825.zh-CN.md`。2026-08-22 的 `real-object-explainer-v1` 继续作为历史基线保留，当前活动实验为 `suspense-stakes-dual-format-v2`。

下一批 4 条按两种格式各生产 2 条，不允许继续套用统一时长：

1. 动作谜题型控制在 `45-75 秒`：真实异常动作开场，经过直觉猜想、推翻和类比回报，答案完成后立即结束。
2. 利益冲突型控制在 `180-300 秒`：从具体订单、价格或人物处境出发，至少两次升级问题，进入利益相关者、钱、规则和现实代价。
3. 两种格式都不得在前十秒交付完整答案。第一层解释必须自然生成第二层问题，否则缩短或淘汰命题。
4. 研究中的来源身份、权利状态和非关键限定留在内部证据；只有遗漏后会造成实质误导的边界才进入旁白。
5. 通用环境 B-roll 只能承担短暂情境或转场。核心对象、动作、价格或关系没有可用画面时，在 Topic Gate 淘汰命题。
6. 每条必须明确属于哪一种格式；四个实验槽位不能相互挪用，也不能用第三种临时模板补数。

封面默认使用一个清晰真实对象特写和一个 8-14 字反差或现实后果，环境不得成为唯一主体。发布适配器报告封面上传成功后，仍要核对平台实际展示像素；小红书只允许真人通过官方入口完成选择和复核。

每条发布后按 `2h / 24h / 72h / 168h` 追加指标快照。优先比较同平台的曝光与点击、2 秒或 3 秒跳出、平均观看秒数、平均播放比例、完播、收藏、分享、评论和关注。目标是 3 秒跳出低于 30%，动作谜题平均播放比例高于 60%，利益冲突平均播放比例达到 35%，显性互动率达到 2%，并出现可观察关注增长。完成 4 条新视频或到 2026-09-22 时必须复盘；不足两条同时改善首段留存和互动即停止当前假设。

### 4.2 当前平台调研

以 B站为主调研近 6-12 个月的成熟解释型内容、搜索结果和评论问题，记录可核验的案例、开头结构、真实案例承载方式、画面组合、系列潜力和中文同质化。其他平台只在能补充当前命题的需求或同质化判断时查看，不默认做全平台矩阵。

平台报告、创作者案例和播放量只能证明内容形态存在。它们不能证明新账号必然获得流量，也不能替代题目级素材核验。

### 4.3 开放候选池

提出 8-12 个差异明显的候选，每题都要同时回答受众钩子、知识收益、核心矛盾、一手来源、动态素材、替代视觉、短版与长版适配、同质化和风险。

只有概念没有案例、只能侵权搬运、依赖本人拍摄挑战、属于医疗法律金融建议，或退回 AI 工具资讯与制作流程的题目直接淘汰。

### 4.4 三题可行性核验

为 3 个方向不同的入围题实际打开并核验一手来源和动态素材。命题调研阶段至少记录：

- 原始 URL、发布者和权利状态；
- 发布日期、可见清晰度和大致可用段落；
- 计划使用的完整窗口是否原生无平台角标、账号角标、下载标记或其他来源水印；
- 能承担的具体观点；
- 画面角色和替代理由；
- 近期相似内容、评论问题和同质化缺口；
- 不超过 15 秒的开头承诺与 3-5 段叙事骨架。

此阶段不下载或批量入库素材，不生成 SHA-256、`sourceStart/sourceEnd` 或 start/mid/end 代表帧；这些属于 Topic Gate 批准后的 Material Gate。

来源不可访问是覆盖缺口，不是对事实的反证。品牌画面可以说明操作或情境，但不能单独证明监管、统计或环境结论。

动态素材必须原生无平台或来源账号水印。不得把裁切、遮挡、模糊或覆盖水印当作可行方案；如果核心叙事只能依赖带水印视频，且没有权利可判断的无水印替代素材，该命题在 Topic Gate 直接淘汰。

### 4.5 Topic Gate

向用户提交发布复盘、候选池、3 个入围题、证据与素材方案、风险和唯一推荐。此时不得创建 canonical project。

用户批准的是一句话受众命题。评分只用于候选比较，不进入成片叙事，也不代表市场验证。调研任务到此结束；画幅和生产授权在后续生产任务中确认，默认仍为单横版 `16:9 / 1920x1080 / 30fps`。

### 4.6 Canonical production

另开生产任务并获得明确授权后，创建独立 `project.json`，完成 Research Gate、素材清单、原创中文叙事、不可变候选窗口和 `materialQualityReview`。逐幕 `platformWatermark` 必须明确记录为 `absent`、`present` 或 `not-applicable`；缺失复核或 `present` 均禁止渲染。

生产任务不得继承 Topic 调研中的候选池、网页导航树、下载日志和完整对话历史。只交接已批准的一句话命题、已核验来源、证据边界、素材线索、目标信号和批准指纹。Canonical project 创建后，用阶段投影读取必要上下文：

```bash
npm run project:context -- --brief=content/projects/<project-id>/project.json --stage=research
npm run project:context -- --brief=content/projects/<project-id>/project.json --stage=material
npm run project:context -- --brief=content/projects/<project-id>/project.json --stage=delivery
```

完整 `project.json` 仍是唯一事实源；阶段投影只是只读上下文，不得反向覆盖 canonical。来源处理队列默认以 3 路有界并发运行，在任一来源结束后立即补槽位；可用 `SOURCE_PROCESSING_CONCURRENCY=1..8` 调整，但不得用无上限并发冲击本地 Whisper、CPU 或外部模型额度。同一项目的来源结果必须通过 canonical 文件锁逐次归并，锁内不得执行网络、转录、FFmpeg 或模型调用。来源处理、转录和渲染等长任务必须运行到终态或明确超时，只在状态变化时返回摘要，不得由模型高频轮询。情境素材已经满足动态覆盖预算时，冗余来源失败一次即可淘汰，不得阻塞 Research Gate。

事实必须由一手资料或明确归因的来源声明承担。画面按实际能力分为直接证据、操作示意、相关情境、原创信息层和 AI 示意；替代画面不能冒充真实记录。

#### 动态素材预算与静态例外

当前“日常有因”普通受众解释视频默认把动态素材作为可计算的生产约束，而不是渲染后的主观评价：

- Creative Brief 和素材方案在渲染前记录计划动态秒数、计划总时长与目标比例；用户未另行指定时，实际动态视频至少覆盖成片 70%，优先接近或达到 80%。
- 实际比例按最终 `timeline.json` 计算：累加已启用场景中已选候选 `mediaType=video` 的输出时长，再除以成片总时长。静态图添加推拉或其他程序化运动仍按静态计算。
- 同一窗口循环、慢放、重复用于不同观点、无语义关系的通用 B-roll，以及只为满足数字而延长空镜，均不得用于提高比例。
- 静态场景只保留给公式、阈值、表格、产品对象或其他需要稳定阅读的教学信息。每个静态例外都要记录它比动态替代更适合学习目标的原因，并在真实桌面和移动播放器中复核可读性。
- Topic Gate 已知无法获得足量已清权、无平台水印且语义可用的视频窗口时，应降低素材可行性评分并淘汰、缩短命题或更换题目，不得先生产静态版本再靠无关动态素材补足。
- 验收同时报告计划比例和最终时间线实算比例；只有后者可以作为交付结论。

#### 素材职责、观众语言与开场回归

2026-08-19 的微波炉机制样片经历了四次明显不同的视觉方案，这次迭代暴露的不是单一素材问题，而是素材职责没有先分清：

| 版本 | 主要方案 | 结果 | 学到的边界 |
| --- | --- | --- | --- |
| v1 | 大量原创程序化机制画面 | 语义可控，但质感生硬，观看感像内部演示 | 能准确画出来不等于适合做整片主体 |
| v2 | 优化口语旁白与原创动画质感 | 语义和表达进步，但统一自制画面仍有明显 AI 感 | 旁白质量与视觉资产质量必须分开评估 |
| v3 | 六幕全部改成网页实拍 | 现实感明显提升，但爆米花只能展示受热结果，无法直接解释分子机制 | 实拍占比不是越高越好，素材必须承担它真正能表达的观点 |
| v4 | 五幕实拍加一幕分子 2.5D 示意 | 实拍覆盖约 83%，不可见机制由唯一程序化段解释，当前自动验收通过 | 最合适的是按职责混合，不是“全实拍”或“全自制”二选一 |

后续普通受众解释视频按以下规则执行：

1. 现实对象、人物、操作、使用情境和可见结果优先使用清晰、已清权、原生无平台水印的网页真实动态素材。真实画面提供质感、可信感和动作连续性，不要求它单独证明旁白中的抽象机制。
2. 分子运动、信号路径、场强分布、隐藏结构和抽象因果等肉眼不可见内容，可以使用简洁原创信息层或程序化 2.5D 示意。示意只讲当前一个机制，不为了展示制作能力扩展成完整三维场景。
3. 不把动态素材预算误解为固定配方。微波炉 v4 的约 83% 实拍是该命题的结果，不是所有题材都必须复制的比例；真正约束仍是至少 70%、优先接近 80%，以及每幕画面职责成立。
4. 旁白面向观众只需完成一个认知闭环：看到什么问题、为什么大致会这样、接下来能怎么做。事实边界继续严格核验，但来源许可、素材替代、模型、审片和非关键限定留在内部证据，不能把严谨写成报告腔。
5. 前三秒使用“真实对象 + 明确动作 + 一句问题或反差”。微波炉样片有效的开场是结束加热、开门取食，同时出现“外面烫了，里面还冷？”；标题负责放大冲突，不能替代真实动作。
6. 选窗必须保留动作 payoff。微波炉 v3 的牛排窗口 `0.00s-6.07s` 在切面清楚出现前结束，后移到 `1.10s-7.17s` 才让动作结果进入成片。以后对开门、切开、翻转、移动、爆开或 UI 状态变化，除 start/mid/end 外还要查看候选终点后的短区间，再锁定不可变窗口。
7. 用户反馈要拆成独立轴记录。语义进步不代表视觉通过，真实素材增加也不代表机制表达通过；至少分别判断观众语言、素材质感、前三秒、语义匹配、动作完整和字幕可读性，避免一次修改把已经改善的维度一起推翻。

这组经验只约束当前自营解释型内容，不改变 VideoBrief 对其他题材的通用素材能力。正式成片仍需按 canonical project 记录每幕的 `evidenceRole`、替代理由、AIGC 状态和最终时间线实算覆盖比例。

### 4.7 正式渲染与验收

在正式预检前，按[会话主导的镜头创作流程](creative-shot-workflow.zh-CN.md)把连续口播落实成可见变化：最难的机制镜头先比较关键帧，再做 5–12 秒局部预览，先修构图、手机可读性、运动与声音意图，合格后作为素材回到 canonical。此步骤是 Codex 内部创作迭代，不新增用户审批 Gate；真实动态预算、前三秒真实动作和正式验收保持原要求。

#### 渲染前的表达试读

2026-09-09 GPT-6 审片回归：动态叙事结尾不得为了延长旁白而保持结果静帧，让观众误以为播放卡住。优先保留真实动作到结果出现，素材不够就缩短结尾。来源归属已经自然交代时，不默认补“自己检验”“不代表真实实验”等免责段落；只有省略会造成实质误导的具体限定才进入旁白，内部验证状态留在审片记录。

先用当前已核实事实写一段连续口播，再按语义和真实动作拆镜头。每幕各写一段独立介绍容易造成反复开场、句长一致和报告腔；换镜头不应自动触发重读产品名或总结。

2026-10-18 用户确认后续优先采用“连续音轨先生成，本地再截取”：同一条视频或完整章节先定稿，合成一条连贯旁白，再按转写时间和真实停顿切出各幕，保留原始长音轨、原始气口与裁切区间。短片优先整条一次，几分钟内容先按完整章节验证，不为省请求凑多余文稿或混入无关选题；缺少可靠边界时先复核或调整本地切点，不自动消耗 N 次逐幕重录。字幕与镜头跟随实际音频，已确认素材窗口不足时依既有规则换窗或改稿。免费层的日请求数与付费的音频量计费是两件事，付费时未采用的生成部分也计费。

2026-10-20 用户试听后接受多模型备用：创作首选 Gemini 3.8 Flash TTS，备用候选按 3.8 Flash-Lite TTS、3.1 Flash TTS Preview、2.5 Flash Preview TTS 的顺序检查实际可用性；这不是自动修改现有项目配置或运行时静默回退。不同视频可轮换，同一条视频保持同一模型和声线；需要切换时先明确记录，再整条或完整章节重新生成并复核。优先复用已有音轨，避免为节省次数牺牲连贯性。控制台曾为四款分别显示非零免费额度，但额外共享限制未验证，不承诺固定合计40次/天；同项目不同 Key 共享额度。升级 Paid Tier 后 TTS 按付费价格计费，不是先用完免费次数才收费，启用计费仍需用户明确授权。试听结果见[中文旁白实测](voice-audition-results-20261018.zh-CN.md)。

本轮复用了 Gemini 3.8 的约 18 秒真实音轨，按转写区间和静音中点切成四段，完整解码后重拼的 PCM 与原始解码样本完全相同，未调用 TTS；收据在 `output/voice-benchmark-20261018/local-cut-proof/attempt-02/receipt.json`。旧的字数/停顿自动匹配在同一音轨上拒绝了边界，失败记录保留在 `attempt-01.json`。这只验证本地截取与复用，不证明几分钟生成、主观听感或正式成片已经验收。

现有正式 batch 会删除选中的分幕静音并补尾留，普通分割失败也可能回退到逐幕请求；Gemini 3.8 返回已有 WAV 时，生产适配还需处理 WAV/PCM 区分。正式接入该制作方式前应修正并验证这些路径；当前采用会话主导的本地裁切，不把试听脚本成功当作自动生产链已兼容。

正式选窗锁定前，选取开场和一个解释转折，合计约 15-25 秒，用当前项目配音配置生成试读。先只听声音，检查句子是否一遍听懂、重音是否落在动作或结果上、停顿是否符合意思、专名是否正确，再结合候选画面看动作结果是否完整。试读是内部表达实验，不代表正式预检、Material Gate 或成片验收通过。

比较版本时保持事实、配音引擎和音色一致，一次只改变措辞或语速；不要同时换稿、换声、换画面后宣称某项修改有效。不能通过加速硬塞旁白、随机语气词、假笑、假失误或编造“我试过”来制造真人感。真实体验必须有记录，产品宣传也不能把官方演示改写成亲测。

审听结果按观众语言、声音自然度、节奏和画面匹配分别记录。自动时长检查只能验证节奏约束，不能给出“像真人”的通过结论。发现问题先改稿或配音设置，再运行正式预检和绑定当前版本的素材验收。

表达试读现有可执行入口为 `node scripts/preview-voiceover.mjs`：默认只输出计划，显式 `--render` 才使用当前项目声线生成隔离音频。观感排查入口为 `node scripts/review-audience-experience.mjs`，只定位时间点、声音配置与跨片重复备注，不自动评定自然度。用法、同条件比较和 2026-10-17 两片回归见[观感优化与对照流程](audience-experience-optimization.zh-CN.md)。Edge 的 `voiceProfile` 名称不代表它能执行自然语言表演指令。

结构化编辑审查模板默认 `pending`。每项先写本片时间点和实际观察，再决定状态；不得整批复制通过备注。转写准确、尾留短、无冻结分别是技术证据，不能替代声音交流感、动作回报和连续观看。改过稿、声线或机制镜头后，正式预检与验收仍须绑定新版本，不回写已发布历史收据。

配音提供方明确返回永久性失败（例如地区不支持）时，批量生成不得再回退成逐幕重复请求。需要切换项目已有配音引擎时，应明确记录并告知用户，重新运行语音预检；不能把替代音色描述成原音色。

当前版本已通过技术检查时，可使用 `/short-video?project=<project-id>&acceptance=1` 进入本地审片。该入口允许待语义检查和审片失败的版本播放以便修改，但不改变验收状态；过期、文件缺失或技术检查未通过的版本仍不能通过该入口播放。

按以下顺序执行：

1. `video:preflight:voiceover` 生成或命中正式 TTS，按真实语音验证全部已选窗口和不超过 `1.25s` 的每幕尾留；
2. `materialQualityReview` 当前且 8/8 或全部启用场景通过，包括每幕无平台/账号水印复核；
3. 正式 FFmpeg 渲染；
4. technical proof；
5. 视频流和音频流完整解码；
6. canonical、timeline 与 manifest 的窗口逐幕一致；
7. start/mid/end 语义审查；
8. opening、visualReadability、pacing、subtitleReadability、pronunciation、platformFit、cta 七项编辑质量审查；
9. 桌面 1440×900 与移动 390×844，非静音、1 倍速从 0 播放到真实 `ended`。

自动化通过后停在 Delivery Gate。没有真人批准当前视频哈希时，不打包、不上传、不发布。

Delivery Gate 前即可生成本轮耗时、请求、缓存、失败成本和可选 Codex 会话 token 报告，不需要等待打包：

```bash
npm run project:production-report -- \
  --brief=content/projects/<project-id>/project.json \
  --session=/absolute/path/to/codex-rollout.jsonl \
  --until=<delivery-gate-iso-time>
```

提供方未返回或仓库未记录的 token 与费用必须保持 `null` 或明确标记不可用；不得从请求数估算为事实。

场景时长必须跟随真实 TTS 旁白，而不是直接沿用候选素材窗口。每幕旁白结束后只保留短尾气；technical proof 按 `docs/video-render-pipeline.zh-CN.md` 的门槛拒绝多秒无字幕、无音频的等待。完整审片还要在用户指出的具体时间点前后复核切幕，不能用音轨存在、总时长一致或逐幕中点非空代替节奏检查。

当前自营解释型视频的编辑文字默认从简：底部逐句字幕承担连续阅读，左上角 Eyebrow、Title、Deck 不得在每幕重复复述旁白。只有学习目标确实需要、真实画面无法直接表达且不会遮挡主体时，才增加简短原创信息层，并在桌面和移动视口复核。

正式封面也属于发布素材。封面使用的外部图片或视频帧必须单列来源、许可和必要署名；封面来源未进入成片时，仍要进入发布文案的权利说明。重剪后不得沿用与当前素材清单或署名链不一致的旧封面。

已审封面要保存在生成导出目录之外，并由 canonical project 的 `platformCopy.coverAssetPath` 明确引用。production package 只能原样复制该资产，并在 manifest 与 package receipt 中记录封面 SHA-256；打包、重新打包和 Publication Gate 都不得静默回退到自动首帧封面。

封面验收必须看最终 PNG 像素，不能只看生成命令成功；重点检查换行转义、中文字体、裁切和平台缩略图安全区。发布包的 AIGC 状态要同时检查生成画面、合成语音和其他生成内容，并优先映射到平台专用声明字段。平台没有专用字段且规则明确要求正文披露时，才在简介追加最短必要声明。

平台标题和简介按正常创作者口吻写。正文只保留观众问题、内容价值、必要事实边界和 CTA，不展示 TTS 型号、VideoBrief 工作流、资料核验、剪辑、字幕、封面制作、素材质量审计或“未使用 AI 画面”等内部过程。事实来源、完整素材清单和权利证据进入内部台账；只有许可证强制要求的署名才在末尾压缩成一段“素材鸣谢”。如果题目必须依赖大量强制署名素材且显著破坏内容体验，应在选片阶段换用免署名素材，而不是发布时删掉法定署名。

### 4.5 多平台发布与排期

每个平台建立独立发布目标，分别保存批准、投稿时间、定时时间、平台稿件号、投稿记录 URL、真实公开 URL、实际发布时间、投稿文案快照和历次数据快照。排期不能当成发布，审核通过也不能当成公开可见；到点后仍需核验公开页，再把目标更新为 `published`。项目级 `publication_status=published` 只表示至少一个平台已有可核验的真实发布事实，其他目标继续保持各自状态。复盘前，只有允许自动采集的平台才能通过 `project:publication-ledger` 复用保存的账号状态；人工发布平台先人工录入 canonical project，再使用 `--skip-collect` 派生台账。`0` 表示平台明确返回零，`null` 表示本轮未取得，二者不得混用。跨平台 Markdown/JSON 台账只从 canonical projects 生成，不手工重复维护。

当前阶段只选择 1-2 个主平台做真实反馈实验。B站、视频号、小红书、抖音和 YouTube 可以进入同一目标清单，但标题、封面、说明、标签、AIGC 声明和 CTA 必须按平台分别复核；不得把同一套文案和素材不加判断地批量铺到所有平台。没有当日官方规则证据、账号授权或稳定上传适配器的平台，先纳入人工发布流程，不伪装成已自动接入。

#### 小红书人工发布边界

2026-08-18，当前自营账号通过 `social-auto-upload` 自动打开小红书发布页、填写内容并提交视频；对应运行记录为 `2026-08-18T10-10-03-179Z-23cb2caa`。2026-08-19 19:22，账号收到“多次利用 AI 托管进行发文/互动”的审核处置，并被限制发布、评论、私信和群聊等功能至 2026-08-26 19:22。平台没有披露具体检测信号，不能把某一次调用断言为唯一原因，但仓库中的自动投稿和自动采集事实与处罚时间线足以将这条路径视为已验证的账号风险。

此后小红书固定采用人工交接：VideoBrief 生成已审成片、封面、平台文案、AIGC 声明建议和发布检查清单，真人只通过小红书官方 App 或官方 Web 完成投稿、查看和数据抄录。不得再用第三方上传器、浏览器自动化、AI 托管或保存的 Cookie 执行登录检查、发布、浏览、互动和指标采集；生成跨平台台账时只读取 canonical project 中已人工录入的数据。处罚期间不得通过重试、换设备或换登录态验证是否仍会触发风控；需要申诉时如实说明使用过第三方发布辅助工具、已经停用，不得否认已有运行记录。

这项限制不等于禁止在创作过程中合理使用 AI，也不能由正确填写 AIGC 标识解除。内容合成声明和账号操作方式必须分别审核。其他平台是否允许程序化上传，继续按各平台当日官方规则和账号实测独立判断，不从小红书案例直接外推。

## 5. 证据分工

| 证据或画面 | 可以承担 | 不能单独承担 |
| --- | --- | --- |
| 一手资料 | 法规、定义、统计、企业原始声明 | 画面体验与观看节奏 |
| 真实动态素材 | 操作、人物行为、产品形态、事件现场 | 素材没有直接展示的统计或因果结论 |
| 语义相关素材 | 情境、机制、类比、氛围 | 特定人物、产品、事件或结果的真实记录 |
| 原创信息层 | 路径、对比、条件、抽象机制 | 没有来源支撑的新事实 |
| AI 生成或合成画面 | 明确标注的示意、机制、类比和氛围 | 事实发生、人物行为或产品结果的证明 |

## 8. 维护规则

- 新样片加入 `workflow.json` 前，必须有独立 canonical project 和当前 manifest。
- 页面状态必须从项目和 manifest 派生，不得手工写“已通过”。
- 新的跨题材失败案例先修当前成片，再沉淀到本手册或机械检查。
- 评分、用户评价和播放数据分开记录；内部评分不进入 `market_status`。
- 当前双格式实验完成 4 条实际发布视频或到达复盘截止日后，必须更新表现复盘和实验状态；不得用单条播放峰值直接固化格式或延长实验。
- 只有流程在多个仓库中重复出现且仓库契约可以参数化时，才升级为全局 Skill。
