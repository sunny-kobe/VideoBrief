# 视频生产工具协作流程

## 定位与当前验证状态

当前对话的 Codex 负责创意导演、原创镜头编写、调度和编辑判断，VideoBrief 的 canonical project 负责保存生产事实；工具按素材和任务选择，不要求每条视频使用全部插件。项目独立 AI 接口是可选的来源理解与自动策划后端，切换聊天模型不会自动修改它。主流程和渲染契约仍以现有文档为准；镜头创作与局部迭代见[会话主导的镜头创作流程](creative-shot-workflow.zh-CN.md)。

## 组件分工

| 组件 | 主要职责 | 使用条件与输出 |
| --- | --- | --- |
| 当前对话的 Codex | 选题比较、一手事实核验、连续中文叙事、视觉设计、原创镜头编写、调度与审片修改 | 读取当前阶段投影；创作草稿与短段留在 `output/`，合格素材再进入 canonical |
| 项目独立 AI provider | 来源理解、结构化事实整理与自动策划 | 仅对应 API/自动生产入口调用；独立模型配置和调用记录不由聊天模型自动同步 |
| Firecrawl / 可用搜索与浏览器工具 | 查找和读取一手资料、核验素材页面和许可证 | 网页证据不等于清权，不自动下载或代操作小红书 |
| yt-dlp 本地 CLI | 获准生产后的单条公开媒体探测与获取 | 不需要专门安装 Codex 插件；记录版本、状态、元数据，失败时停止或换合法来源 |
| ffprobe + SHA-256 + 本地导入 | 校验下载或外部处理的真实字节、媒体参数和来源 | 元数据声明与实际文件分开核对；流式导入沿用现有实现 |
| 本地 Whisper + 来源理解 | 默认转录、章节、代表帧、事实与不确定项整理 | 本地路线优先保护隐私；不要与 Descript 重复运行同一完整转录，除非做对照 |
| Descript 插件 | 口播、访谈、教程的转录辅助、候选片段与清理建议；批准后副本编辑 | 不是每份 B-roll 的必经步骤；结果必须保留原片定位并回到 VideoBrief 审查 |
| 现有 TTS provider | 中文旁白、专名规则、时长预检 | 先试听短段，选定引擎后不静默换声；Edge/Gemini 按项目配置选择 |
| FFmpeg | 正式逐幕渲染、拼接、音频归一化、字幕与技术 proof | 唯一默认生产输出；复用现有内容寻址缓存 |
| Remotion / 原创信息层 | 关键帧、短段预览、机制图、数据解释和必要示意素材 | 先修构图、可读性与变化节奏，再把合格资产登记为素材；不自动替换 FFmpeg 正式成片 |
| ImageGen；Runway/OpenArt 等候选 | 必要的原创封面、示意图或合成画面 | 外部视频插件未在本项目验证；仅真实缺口时选一个，记录合成状态、许可和费用 |
| Adobe/Higgsfield/HeyGen/vidIQ 等候选 | 指定版式、广告、数字人、翻译或 YouTube 调研 | 非默认依赖；安装、连接、中文效果和可下载输出须分别验证 |

## 从命题到交付

1. 明确观众、唯一问题、学习收益、时长和平台。默认只做 16:9、1920x1080、30fps。
2. 核验少量入围命题的一手证据、动态素材、原生水印和权利可行性。自营命题调研阶段不批量下载、不创建项目，获得 Topic Gate 批准后再生产。
3. 创建独立 canonical project。获准的公开素材按需用 yt-dlp 或直接下载获取；记录原始 URL、发布者、标题、取得时间和状态。拒绝登录/Cookie、DRM、付费墙及权限绕过。
4. 对本地文件计算哈希并用 ffprobe 核对时长、画幅、帧率和编解码器；导入 `sources[]`。官方或可下载不代表 `rightsStatus=cleared`。
5. 按素材类型理解：真实动态画面检查动作与结果；文档抽取事实；口播素材优先考虑 Descript 的只读转录/候选分析，或沿用本地 Whisper。研究 Gate 只接受可定位且已确认的事实。
6. Codex 根据证据和可用镜头写一段连续原创中文口播，形成开场动作、问题、机制、影响和收束，再按意思与动作拆幕。明确每幕观众应看到的变化、画面角色、重音与停顿；机制难点先比较关键帧并做 5–12 秒局部预览，按[镜头创作流程](creative-shot-workflow.zh-CN.md)修正后再生成素材。
7. 逐幕选窗并登记画面角色、权利、水印和替代理由；旁白、标题、字幕和可见画面表达同一观点。自营解释片真实动态预算按最终时间线至少 70%、优先 80%，不靠循环或无关 B-roll 补数。
8. 生成短段配音并审听，再执行真实旁白时长预检；通过后写入绑定当前版本的素材质量复核。窗口不足时改稿、换窗或缩小命题，不静默延长已确认窗口。
9. FFmpeg 正式渲染并复用合格场景缓存，生成 manifest、字幕和技术 proof；完整解码、核对时间线、响度、静音和冻结。
10. Codex 逐幕审查 start/mid/end、字幕、节奏、动作完整性和桌面/手机可读性；真实播放器完整播放到 ended。工具通过不等于真人观看批准。
11. 用户完整审片并批准当前视频哈希。生成已审稳定封面、平台文案、必要署名/AIGC 声明和版本绑定发布包；未经明确授权不上传或发布，小红书仅真人操作。
12. 人工发布后记录真实结果和反馈。分开记录 technical、rights、publication、market；用观众理解、完播与返工成本指导下一条，不用内部评分冒充市场验证。

## Descript 的默认操作契约

先查当前工具是否实际加载，再检查目标项目。只对明确允许云端处理的素材上传；默认私有项目，不上传整个项目目录或不必要的证据。上传和付费额度边界由当前任务授权决定。

### 第一步：分析，不编辑

给 Descript 一份口播源和明确任务，要求转录、源时间码、候选片段、口头语/重录清单及预计删除时长。不能定位原片的结果只作为建议，不自动锁定候选。

推荐任务正文：

> 只分析，不修改项目，不压缩停顿、不删画面、不发布。基于现有转录列出适合当前观众问题的候选片段，每项给出原始媒体名、原片开始/结束时间、对应文字、完整上下文和推荐原因。另列明显口头语、重录与重复句以及预计删除秒数。无声但有动作、演示、阅读或结果展示的窗口保留；不确定时标注，不猜测时间码。请用中文报告。

### 第二步：确认后编辑副本

保留原片和原 composition；确认能够创建独立副本后才执行批准的逐项清理。明确最短停顿、最大允许删减量、保护窗口和目标时长；超限时返回建议，不执行。禁止一句笼统的“清理所有停顿”。只有叙事目标明确需要时才添加字幕、音频处理或 B-roll。

### 第三步：回收并复核

记录 project/composition/job ID、输入哈希、指令、额度、编辑清单和可核实的时间码映射。保留源时间与编辑后时间两套坐标，不能直接把剪后时间写成原片 `sourceStart/sourceEnd`。

能获得外部编辑文件时，将它作为新派生 source 导入，保留原片关联、处理说明和权利链，再走现有选窗与验收。不凭空新增 canonical 字段；额外工具收据可存独立证据文件并通过现有备注引用。

`publish_project` 创建分享页，不等于普通本地导出，即使 private 也属于外部发布操作。仅在明确授权后调用，不因导出失败自动改 public/unlisted。没有可下载且可复核的文件时，只交付候选建议或外部审阅链接，不称已集成成片。

## 利用效果的衡量

按每条视频记录素材获取时间、首次可看版本时间、审片/返工时间、外部额度、失败次数和采纳候选数。Descript 只有在减少总人工处理时间且不增加错剪、失真或恢复成本时才扩大使用；本次样本尚不足以证明收益大。不要求工具使用率最大，要求观众价值、质量和总投入的收益最大。
