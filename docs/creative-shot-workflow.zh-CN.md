# 会话主导的镜头创作与短段迭代

VideoBrief 的创作入口是当前对话：用户给出目标或审片意见，Codex 负责叙事、视觉设计、编写原创镜头、调用工具和修改。先把最难的一个镜头做对，再交给既有生产链，可以避免花时间渲染一条画面清楚但主要靠旁白解释的成片。

这是创作方法与素材工具说明，不新增审批 Gate。Codex 在已授权的制作范围内完成内部比较和修改，用户继续通过对话审看结果；正式素材、旁白、语义、浏览器播放和交付验收保持原要求。

## 谁在创作，哪个模型被调用

| 位置 | 职责 | 当前任务如何使用 |
| --- | --- | --- |
| 当前对话的 Codex | 创意导演、原创中文作者、视觉设计者、工具编写与操作人员、审片修改者 | 可直接根据阶段投影写稿、编写动画和调用本地渲染器；无需先经过项目独立 AI 接口 |
| VideoBrief 独立 AI provider | 可选的来源理解与自动策划后端 | 显式执行对应 API、来源处理或自动生产入口时才调用；配置由项目服务读取，切换聊天模型不会自动修改它 |
| Canonical project | 保存事实、叙事、素材、已确认窗口、配音设置和验收状态 | 正式 FFmpeg 输出以它为输入；对话草稿、实验 MP4 和工具收据不能替代它 |

判断一次制作是否用了独立接口，要检查实际执行的入口与 AI 调用记录，不能只看聊天模型或 `.env.local`。会话主导的创作记录与项目 API 调用收据应分别保留；`ai.calls` 为空不能说明当前对话没有进行创作。

## 从学习目标到可用镜头

### 1. 写清一个学习目标和前三秒承诺

沿用 Topic Gate 已批准的观众问题，用一句话写“看完能理解或做到什么”，再写前三秒将兑现的可见承诺。例如“为什么外面烫了，里面还冷？”对应开门、取食或切开后的真实结果。先让真实对象发生动作，短标题强化问题。

当前自营解释片仍优先用已清权、原生无平台水印的真实动态素材，按最终时间线至少覆盖 70%、优先接近 80%。原创动画用于实拍无法表达的机制或信息，不能以全动画能力探针替换正式题目的素材职责和预算。

### 2. 先写连续中文口播并试听

基于已核实事实写一段连续口播，再按意思和动作拆幕。换镜头不自动重读主题、产品名或重新总结。沿用[表达试读](self-owned-explainer-production-playbook.zh-CN.md#渲染前的表达试读)，先只听开场和一个解释转折，再与画面组合。

每个叙事点标出重音、停顿和语速意图，例如“外层已经热了／中心，还慢一步”。这些先作为内部创作说明；最终时长必须用当前项目的真实 TTS 检验，不能凭字数或标点声称声音已经自然。

### 3. 指定观众应看到的变化

每幕只写一个具体视觉变化，并注明画面角色。让变化承接旁白的动词与因果，避免只放一个相关对象再靠字幕讲完。

| 创作问题 | 内部说明示例 |
| --- | --- |
| 旁白里的因果是什么？ | 停止加热后，热量仍会从较热区域传到较冷区域 |
| 观众应看到什么变化？ | 外圈由橙色变淡，中心由蓝色变暖；传导方向从外向内显现 |
| 画面承担什么角色？ | 原创机制示意，不是温度实测或特定食物的真实记录 |
| 何时开始，何时完成？ | “往里走”时方向出现，停顿时中心的变化完成，切走前保留结果 |
| 声音怎样配合？ | 重音落在“往里”；是否需要音效由这个变化决定，不默认加入持续音床 |

设计过程可以留在 `output/` 的镜头说明中；素材进入正式项目时，把角色、替代理由、来源和合成状态放入已有素材与复核记录，不新增临时 schema 字段。

### 4. 先比较两个设计关键帧

先为最难的叙事点做两个局部构图方案，保持事实、旁白和配色基线一致。可以比较“剖面放大”与“横向路径图”，或同一构图的标注位置；无需为每幕做两套完整动画。

在真实桌面和手机显示尺寸查看：第一眼是否知道看哪里，核心变化有没有空间，关键字能否直接读到，底部是否给正式字幕留出空间。择优后进入运动预览。静帧能检查构图，不能证明转场、运动或声音已经通过。

### 5. 做一段 5–12 秒的关键镜头预览

选择机制最难、文字最多或最容易错配的一段，先完成一个完整的“起因 → 变化 → 结果”。已有素材本身足够表达时，优先改善选窗、局部标注或剪辑，不默认重造动画。

预览先检查构图与手机可读性，再检查出现顺序、速度、方向和结果停留；试听时再检查重音、停顿和音效是否帮助理解。每次修改针对具体问题，例如“方向出现太晚，听到传导时仍看不到路径”，避免只有“更高级”“加点动效”的指令。默认不用推拉掩盖静态素材不足，固定构图中的物体状态变化也可以形成有效节奏。

配乐和音效是具体创意选择：可以不要，也可以在转折或结果处使用已清权音频。当前 TTS 与音频归一化能力不代表已经实现自动配乐、音效设计或混音；没有实际声音文件和试听证据时，只记录声音意图。

短段看懂且节奏成立后才生成完整镜头资产。只对当前重点做局部比较，不把每个设计动作变成用户逐项审批。

## 本地镜头工具与正式素材的边界

工具入口为 `video:creative-shot`，`prepare` 准备场景上下文，`preview` 生成关键帧，`render` 渲染原创镜头，`inspect` 检查输入与产物是否过期。每个 `take` 保存一个版本，已有预览或视频拒绝覆盖，修改后换新的 `take`。

```bash
npm run video:creative-shot -- prepare --brief=content/projects/<project-id>/project.json --scene=<scene-id> --duration=8 --work-dir=output/creative-shots/<project-id>/<scene-id> --take=take-01
# Codex 读取 take-01/shot-input.json，并在工作区编写 Remotion 入口；Composition 的宽高、帧率和帧数与其中 spec 一致。
npm run video:creative-shot -- preview --brief=content/projects/<project-id>/project.json --scene=<scene-id> --entry=output/creative-shots/<project-id>/<scene-id>/source/index.tsx --composition=<composition-id> --frames=0,60,180 --work-dir=output/creative-shots/<project-id>/<scene-id> --take=take-01
npm run video:creative-shot -- render --brief=content/projects/<project-id>/project.json --scene=<scene-id> --entry=output/creative-shots/<project-id>/<scene-id>/source/index.tsx --composition=<composition-id> --work-dir=output/creative-shots/<project-id>/<scene-id> --take=take-01
npm run video:creative-shot -- inspect --brief=content/projects/<project-id>/project.json --scene=<scene-id> --work-dir=output/creative-shots/<project-id>/<scene-id> --take=take-01
```

工具默认只写 `output/`，不改 canonical、不自动清权、不调用独立 AI API，也不自动批准素材。它帮助 Codex 读取一个场景并预览自己编写的镜头；Remotion 入口是 Codex 明确选择的可信工作区代码，工具不是任意代码执行沙箱。生成的 MP4 仍是待视觉复核的素材，工具成功退出不能证明观众能看懂。

默认镜头时长取现有候选窗口除以播放速率；`prepare --duration=8` 仅为原创镜头设置八秒目标，不改原素材的锁定窗口。画幅、帧率从 canonical 读取，缺省为 `1920x1080 / 30fps`。输出保存在 `work-dir/take-01/`：`shot-brief.md`、`shot-input.json`、准备收据、关键帧与预览收据，以及 `clip.mp4` 与渲染收据。首/中/末帧始终保留，`--frames` 用来补充转折帧。

CLI 的 `preview` 只生成静帧；要检查 5–12 秒的连续运动，需要对短段 composition 执行 `render` 并播放 `clip.mp4`。这里的 `render` 生成素材实验，不是 FFmpeg 正式成片，也不会写入生产验收。

`render` 要求同一版本已有且未过期的预览，合成规格必须与 `shot-input.json` 一致。预览与渲染状态仍是 `awaiting_visual_review`；`technical.decodePassed` 只说明技术解码结果，`inspect` 返回 `stale` 时先重新准备和预览，不沿用旧素材或旧判断。

复核后，通过现有本地素材导入能力把真实 MP4 字节保存为稳定素材，登记来源、原创/合成状态、权利依据和事实边界，建立候选并明确完整时间窗口。正式场景与已确认候选的 `sourceId/sourceStart/sourceEnd` 必须一致；随后重新运行真实旁白预检，再完成绑定当前素材的 `materialQualityReview`。不直接把实验路径或旧验收写成当前成片通过。

## 连续观看决定创作结果

正式 FFmpeg 输出继续执行技术 proof、完整解码、时间线核对、逐幕 start/mid/end、字幕和桌面/手机真实播放器检查。额外的创作判断应落实到修改：

- 隐藏字幕或暂停旁白，关键路径、对比和状态变化是否仍可辨认？这是机制表达诊断，不替代事实核验。
- 以手机竖持时的实际横版显示尺寸观看，是否出现只在桌面大图上能读的小字？读不到就减少文字、放大关键区域或改构图。
- 连续听看，画面变化是否落在对应词语附近，动作结果是否出现后才切走，静止是否有阅读或观察的意义？
- 从开场完整播放到片尾，是否真的回应了前三秒承诺，是否还有报告腔、重复解释或只靠字幕传递的重要机制？

发现问题先修改 canonical 或素材并重新生成受影响部分。`proof.passed=true`、抽帧非空和 Gate 标签都是生产证据的一部分，不能代替连续观看与具体创作判断。用户的当前视频哈希交付批准仍按现有流程执行。

## 记录实跑和未验证项

每次内部迭代保留输入、关键帧或 MP4、修改原因、实际操作与渲染耗时，以及未检查项目。优先记录“标签遮住传导方向，移除后重新检查第 330/420 帧”这类可复核证据；不伪造主观分数、模型胜率或省时比例。

上一轮探针使用稳定的“左文右图”布局、三段标题与说明，桌面机制草图清楚，但整体仍像讲义。下一条应按当前观众问题减少并行文字，让可见变化成为信息主体，并在短段连续播放中检验；无需为追求动画感而增加没有叙事意义的镜头运动。

本轮独立 API 配置为 `gpt-6.1-sol / medium`；`/v1/models` 与结构化 `/v1/responses` 基础 smoke 通过，但完整叙事请求仍出现 90 秒超时和上游 524，因此稿件由当前对话完成。不要把配置状态或基础 smoke 当作完整叙事成功。

本轮正式视频已重新执行 voiceover preflight、Material Gate、FFmpeg 渲染、技术 proof、逐幕语义审片，以及桌面和 390×844 浏览器一倍速完整播放；交付批准仍保持 pending，未发布。
